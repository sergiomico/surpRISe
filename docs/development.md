# Development commands

Run commands from the repository root. `uv sync --locked` installs the package
in editable mode together with the development dependencies. Environment
activation is unnecessary when using `uv run`.

| Task | Command |
| --- | --- |
| Synchronize the environment | `uv sync --locked` |
| Run regression tests | `uv run --locked python -m unittest discover -s tests` |
| Open JupyterLab | `uv run --locked jupyter lab` |
| Inspect full-source lint | `uv run --locked ruff check src` |
| Build wheel and source distribution | `uv build` |
| Add a runtime dependency | `uv add PACKAGE` |
| Add a development dependency | `uv add --dev PACKAGE` |

## Use the package in another project

From the consuming project's directory, choose a local checkout or a built wheel:

```sh
uv add --editable /path/to/surpRISe
uv add /path/to/surpRISe/dist/surprise-0.1.0-py3-none-any.whl
```

Use the actual wheel filename generated by `uv build`. On Windows, forward
slashes work in paths such as `C:/path/to/surpRISe`. The wheel's distribution
name may be normalized to lowercase; Python imports remain `surpRISe`.

## Reproducibility and builds

Commit intentional changes to both dependency declarations and `uv.lock`.
Do not commit `.venv/`, `dist/`, generated plots, or raw experimental data.
The wheel contains the Python library; the source distribution also includes
tests, runnable examples, documentation, metadata, and the license. Research
notebooks are available in the Git repository and excluded from distributions.

CI runs tests, both headless examples, scoped style checks, and package builds
on Linux and Windows with Python 3.12. A local run does not verify GitHub-hosted
CI or other Python versions. Plotting is optional in the examples; use `--plot`
locally when a GUI is available. For numerical runs use `MPLBACKEND=Agg` if needed.

## Version control

Create focused changes, inspect `git status` and `git diff`, stage specific
paths, and validate before committing. Push to the intended remote branch only
when ready. The project does not require any historical migration branch.

Saved notebook outputs can expose local paths and become large. Review them
before sharing. Moving or editing a file does not remove its older versions
from Git history.
